## 修复：未完成待确认操作时禁止重启服务端

- 文件：`backend/src/guardian/index.ts`
- 调整 `approveActions()`：执行完"本次批准的操作"后，若 `pendingActions.length > 0`，立即回到 `awaiting_user`，回推待确认列表并**直接 return**
- 仅当 `pendingActions.length === 0`（即所有待确认操作均已批准或拒绝）时，才允许调用 `restartServer()`
- 目的：避免出现"还有待确认修复操作却已重启"的违背交互约束行为

## 修复：进程指标 CPU/内存显示 0%（二次）

- 文件：`backend/src/guardian/ProcessManager.ts`
- `getMetrics()` 的 `this.process.pid` 在 `shell: true` 下指向的是外层 cmd.exe。实际进程树为：**外层 cmd (shell) → 内层 cmd (/c) → java.exe (start.bat)**，两层 shell 嵌套
- 第一次修复只找了一层（找到内层 cmd），仍然不消费资源
- 二次修复：
  - 新增 `findDeepestChildPid()` 方法：递归遍历子进程树，每层用 `wmic process where "parentprocessid=..."` 查找子 PID，直至找到叶子进程
  - 每找到叶子 PID 后用 `tasklist` 验证进程名是否含 `java`，确保命中 Java 进程
  - 新增 `getChildPids()` 辅助方法，解析 `/format:csv` 输出
  - PowerShell CPU 查询优化：简化语法，用 `().PercentProcessorTime` 替代 `| Select-Object -ExpandProperty`，更简洁
- rawCpu 解析从 `parseInt` 改为 `parseFloat`，处理 PercentProcessorTime 可能含小数的情况
