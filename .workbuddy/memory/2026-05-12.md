## 修复：进程指标 CPU/内存仍为 0%

- 现象：实际 Java 进程占用 CPU 23%、内存 40%，UI 显示 0%/2%
- 根因：`findAllJavaPids()` 仅依赖 `wmic`，而部分 Windows 版本可能已弃用 wmic，导致静默返回空数组
- 修复：
  - 重写 `findAllJavaPids()` — 三步兜底：wmic → tasklist(java.exe + javaw.exe) → PowerShell Get-Process
  - 搜索不到时保留 `warn` 日志，方便诊断
  - `getMetrics()` 的 `javaPids.length === 0` 条件会在下次轮询自动重试（无需额外改动）

## 修复：停止服务端前 AI 确认启动状态

- 文件：`backend/src/guardian/index.ts`
- 现象：用户点击停止时，服务端还在加载模组（未完成启动），"stop" 命令发送到 stdin 后无响应，15s 超时后强制终止
- 修复：
  - `stop()` 在调用 `processManager.stop()` 之前，新增 `ensureServerStartedBeforeStop()` 阶段
  - 该阶段用 AI 的 `checkCompletion` 反复确认直到服务端加载完成（最多 5 次 × 20s = 100s）
  - 状态设为 `analyzing`，UI 可显示"停止前确认服务端启动状态..."
  - 若 5 次仍未完成，强制进入停止流程（和原来一样 force kill）
